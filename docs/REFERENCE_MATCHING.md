# 单张参考调色：灰度偏色与固定细节映射

当前方向优先完善单张参考调色，P2 批量暂缓。
在 [P1 目标及反馈](P1_EDITING.md) 上增加 `operations(action=task,task_action=anchor_analysis)`。
它读取已留存的实际 C1 预览和明确提供的参考图片，保存数值分析，不写 C1 参数。
审美判断和模块选择仍由视觉客户端完成，之后使用原有 read → adjust → 回读 → 实际预览。

## 摄影师判断流程

1. 分析黑位、暗部密度、主体中间调、白位和高光过渡。
2. 区分暗/中/亮的灰色材料偏色、整体白平衡差异、环境光色及物体本色。
3. 选取少量固定对应细节：漫反射灰白物、合理光照下的肤色、植被、天空、产品或材质。
4. 比较每对细节的明度、红绿/黄蓝方向、色相及浓淡；记录不确定性和保护项。
5. 按差异选择 C1 模块，小幅调整；用同一参考图和同一批细节复测，并看整图是否改善。

参考图的灰色可以刻意偏蓝、偏绿或偏暖。目标是匹配其偏色关系，不能一律校成 a=b=0。
整图低饱和像素不等于真实中性材料，整图平均色也不能证明白平衡错误。
同类细节必须有可解释的语义对应；不同肤色、材质或光线不能盲目追求相同数值。
漫反射小区域优先于单像素、镜面高光、纯黑区域及多颜色边缘。

## 接口

目标必须是当前任务的当前检查点，且脚本可见修订仍与实际预览一致。
参考必须已命名在 brief.references 中。初次 payload：

```json
{
  "checkpoint_id": "当前检查点编号",
  "reference_id": "brief 中的参考 ID",
  "reference_path": "用户明确提供的本机图片绝对路径",
  "reference_sha256": "该文件实际 SHA256",
  "anchors": [{
    "id": "warm-white-wall",
    "role": "相近光照下的白色漫反射墙面",
    "kind": "neutral",
    "reference_box": [0.2, 0.2, 0.3, 0.3],
    "target_box": [0.4, 0.3, 0.5, 0.4]
  }]
}
```

示例坐标不是通用配方。最多十二对细节，kind=neutral/color，参考与目标区域分别选择。
矩形是 EXIF 校正朝向后的预览坐标，范围 0..1，不是 Capture One RAW 或蒙版坐标。
也可用 reference_checkpoint_id 替代 reference_path/reference_sha256，引用同任务已保留的参考检查点。
不支持 RAW、动画、有透明背景的图、多帧 TIFF 或任意 URL；参考文件不超过 32 MiB / 40 百万像素。
不搜索私人图库、不自动上传或复制参考原图。只有视觉附件而没有可读文件时，保持定性分析并明确数值缺口。

ICC 图片按嵌入配置转换到 sRGB，再进行 D50 Lab 测量。无 ICC 的 RGB/灰度图片，
只有明确知道是 sRGB 时才传 assume_srgb={reference:true,target:true}，可以只对缺少配置的一侧启用。
坏配置拒绝处理，不静默忽略。透明像素没有确定的比较背景，不擅自填色。

结果保存在 task.anchor_analyses，最新 ID 在 task.anchor_analysis_id。
reference_plan 可以传 anchor_analysis_id，关联同任务、同当前检查点的有效测量；
修改 brief 的参考或 mode 会停用当前分析，历史结果不改写。

## 报告含义

| 内容 | 可以说明什么 | 不能证明什么 |
|---|---|---|
| L* 五段占比及分位点 | 图像明暗分布、黑白端倾向 | 不同场景必须有同一直方图 |
| 各段 a/b 及低彩度候选 | 描述影调中的颜色分布 | 自动识别中性灰或诊断白平衡错误 |
| 锚点 RGB/Lab 中位数 | 固定细节的明度与颜色关系 | 相机原始颜色或精确 C1 Device RGB |
| reference_minus_target | 参考减当前的 L/a/b、chroma 和 hue 差异 | 可直接填入色温、曲线或滑块 |
| preview_patch_deltaE76 | 渲染后区域中位色的差异描述 | 风格相似度百分比或自动满意判定 |
| neutral_tone_correspondences | 灰色材料的明度对应及参考偏色 | 已拟合的全局曲线或可跨材质复制的配方 |

Lab 轴：+a 为红/品红方向，−a 为绿；+b 为黄，−b 为蓝。灰色材料也保留参考 a/b 目标。
低彩度 hue 不稳定时返回 null。8 位图像、Lab 编码、JPEG 与 ICC 转换限制数值精度。
gray bands 为 L*=0..20 / 20..40 / 40..60 / 60..80 / 80..100。
low_chroma_candidates 使用 C*≤12 且 2≤L*≤98 的启发式筛选，不是中性物识别。

质量警告包括样本过少、亮度混合、颜色混合、接近黑白端点。
这些阈值用于提醒检查取样，不是校准过的可接受误差。存在警告时查看原图、必要时重新选区。
灰度对应顺序倒置，或相同输入明度对应明显不同输出明度，会标记 tone_order_conflict；
可能需要重新匹配光线/材料或使用局部调整，不能由此生成异常全局曲线。

## 持续复测与调色

取得新实际预览、保存检查点并确认细节位置未变后，复用：

```json
{"checkpoint_id":"新检查点","baseline_analysis_id":"已有分析 ID","alignment_confirmed":true}
```

引用原参考哈希及固定矩形，防止换参考或挪动取样去追求更小数值。
参考文件变化、角色变化或目标长宽比明显变化时拒绝直接复用。
同长宽比裁切、物体位移不能靠尺寸自动发现，所以位置对应仍是客户端视觉声明。
位置发生实质变化时重新建立分析，说明旧数字不再可直接比较。

先判断曝光/反差关系，再区分统一偏色、分影调偏色和局部颜色问题：
统一偏色可考虑白平衡；分影调关系可考虑色轮/通道曲线；具体颜色可考虑 Basic/Advanced；
有保护冲突时再缩小作用范围。不要将 sRGB 取色直接作为精确原生 Device RGB 选区。
模块数值依实际照片、原生回读及视觉效果决定，本工具不自动拟合 LUT 或执行像素映射。
每轮仍按 P1 检查改善、保护项和退化；数值减小不代表肤色/材质或整体画面更满意。

## 验证与边界

- 本轮选择性检查：105 passed、1 deselected（沿用旧 recover 接口不匹配排除项，见 P0 验证）。
- 数值测试覆盖中性灰、暖灰保留、原色对抗轴方向、ICC、透明背景、坏配置、参考哈希、坐标、
  接近黑白端、灰度对应冲突；任务测试覆盖固定锚点复用、版本关联、过期/换参考拒绝和零 C1 写入。
- 真实数据检查使用前轮保留的实际 1600px C1 JPEG：同照片绿色饱和度 −6 的前后图。
  用调整后图作已知测试参考。白墙的参考 Lab 约 L=80.8/a=5/b=26，暖偏色被保留而非归零；
  所选植被区域的中位色差约 1.414，匹配到同一测试输出后为 0。
  植被、锈金属和灰墙取样存在混合/纹理警告，未据此宣称精确材料校色或跨照片复刻通过。
- 原选中照片或其状态已不同于旧测试基线，所以本轮只读分析留存预览，没有调整当前 C1 照片。
  同照片输出比较只是功能证据，不是用户参考图或跨场景摄影师验收。
- 在无未决操作时重载本项目执行桥，实际 MCP stdio 仍列出六工具；新动作在 schema 和 context 能力中可见，
  没有 MCP 错误。此轮未通过 MCP 对当前照片执行完整锚点分析/调色，数值接口以软件测试和留存实际图验证为准。
- 尚未收到本次要复刻的实际样图；后续需以该图选择真实对应细节，并验证调整后的整体效果。
- 本次不开发批量、长期偏好库、坐标到蒙版映射或新增宿主参数能力。

实现依据分别是 [Pillow 的 ICC 转换接口](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html)
和 [W3C 对 Lab 的定义](https://www.w3.org/TR/css-color-4/#lab-colors)；接口资料不等于 C1 的实机或审美验收。
